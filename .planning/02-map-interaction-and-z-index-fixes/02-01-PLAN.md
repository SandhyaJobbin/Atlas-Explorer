  <files>app/src/components/map/InteractiveMap.tsx</files>
  <action>
    Per D-01 (INTERACT-03 root cause): Effect B (lines 252-301) clears ALL visual state classes every rAF frame via `el.classList.remove('is-active', 'is-highlighted', ...)` then re-applies them. Combined with `transition-all duration-300` on `.atlas-region` (line 499), this causes border pop-in on every visual state update.

    FIX:
    1. Replace classList.remove with per-class toggle using current state tracking. Maintain a Map<element, Set<className>> that tracks which classes are currently applied. Before applying new state, diff against the previous set and only add/remove classes that changed.

    3. Add transition only on explicit state class selectors in the `<style>` block (e.g., `.is-active { transition: all 0.3s ease; }`, `.is-correct { transition: all 0.3s ease; }`). This way base `.atlas-region` has no transition, only state classes trigger animation.
    4. Keep the rest of Effect B's visual logic unchanged (fill, cursor, etc.).
    
    The `rAF(() => { ... })` pattern stays — only the classList management changes.
  </action>

  </verify>
  <done>

<task type="auto" tdd="true">
  <name>Task 2: Fix hover — remove pointermove, debounce onRegionHover, pointerenter/pointerleave only</name>
  <files>app/src/components/map/InteractiveMap.tsx</files>
  <action>
    Per D-02 (INTERACT-04/05 root cause): Effect A registers `pointerenter`, `pointermove`, AND `pointerleave` handlers for every region (lines 220-244). Small states (RI, DE, DC) have small SVG hit areas, causing rapid enter→move→leave→enter cycles. Each `pointermove` fires `onRegionHoverRef.current(code, pos)` which triggers popup re-render.

    FIX:
    1. Remove the `handlePointerMove` listener entirely (lines 226-230 and its cleanup at line 243).
    2. Add a debounce wrapper (150ms threshold per D-02) around the `onRegionHoverRef.current` call in `handlePointerEnter`: if same code fires within 150ms, skip. Use a closure variable `lastHoverCode` and `lastHoverTime` at the Effect A scope level to track.
    3. Keep `handlePointerEnter` (lines 220-224) — still passes position for tooltip placement.
    4. Keep `handlePointerLeave` (lines 232-236) — still calls `onRegionHoverRef.current(null)` with no debounce needed (always immediate on leave).
    5. Remove `pointermove` from both addEventListener (line 239) and cleanup (line 243).
    
    The 150ms debounce only applies to the enter callback — leave remains instant.
  </action>
  <verify>

  </done>
